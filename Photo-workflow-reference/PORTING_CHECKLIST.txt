LOCAL PLANNING REQUIRED BEFORE EXECUTION

1. Discover the actual computer: OS/version, Apple Silicon or Intel, RAM, free disk, Python and editor, approved input/output folder. Check supported CPU/MPS/CUDA paths from current official documentation and test modest representative inputs. No Mac, Apple GPU, Intel or CUDA run has been established by these experiments. Current inference scripts stay onCPU float32; no automatic device fallback is implemented.
2. Review all code. Fixed absolute roots were replaced with /path/to/photo-workflow-reference placeholders; other scripts use working-directory-relative or file-relative locations. Linux font paths and ru_maxrss unit assumptions are not portable. Preserve algorithms only where useful; do not blindly run or install.
3. Treat observed versions as provenance. The inference venv and host postprocessing environments had different NumPy versions. Build and test a coherent local dependency set rather than installing both snapshots as one lockfile. PyTorch '+cpu' wheels are not universal/macOS pins. Model revisions and file hashes should stay explicit; dependency compatibility needs fresh resolution.
4. Fetch missing weights/configs only from the official model repositories after review, pin revision and verify SHA256. BiRefNet requires its reviewed custom implementation files and a safety review before trust_remote_code. Those implementation files and all weights are omitted. SAM2/ViTMatte use installed Transformers implementations with no remote custom-code import. The guided runner records a model manifest but does not automatically verify its hashes before loading; add preflight verification in a future implementation.
5. Build source validation, RAW handling, color management and orientation/crop alignment. Preserve DNG originals byte-for-byte. Detect actual format, not just extension; reject invalid decoder white balance and ask for/choose an explicit development approach. Never assume an arbitrary developed image fits an existing mask.
6. Design keep-group requests and guided iteration with explicit positive/negative points, correction regions and reviewable trimaps. No natural-language-to-guides adapter, interactive UI, batch queue, safe retry/resume, robust cache, operation history or general object grouping exists here. Do not present handwritten photo-specific polygons as general automation.
7. Keep base masking, approximate color decontamination and artistic shading separately reversible and independently adjustable.24% is an adjustable preference to evaluate, not a global fixed effect. Protect fine web and hair features.
8. Design collision-proof per-photo revisions, named outputs and a manifest. Add assertions, friendly errors and tests before running on valued originals. Many included scripts perform work at import and overwrite derived output filenames; they are research records.
9. Validate original/source integrity, output dimensions/precision/composite equations and native visual quality. The three baseline tests reference the complete ten-photo project and cannot pass in this trimmed archive. They passed again against the original project at packaging time. The included fixtures support local contract checks after adaptation; no full fresh-environment or new model-inference run was performed for this handoff.
10. Return an implementation plan and questions first. Distinguish reusable runner logic from experimental, hand-guided and future functionality. Estimate local memory/disk/runtime from actual measurements rather than old cloud timings.
