Plan a local photo masking workflow

I want an IMPLEMENTATION PLAN ONLY for a photo workflow that runs on my own computer. Read this prompt and the accompanying Photo-workflow-reference folder first. Do not install software, download models, implement the tool or process my photos yet. Ask only the questions needed to produce a sound plan, then stop for my approval.

GOAL
My first priority is a clean, beautiful result; second is minimal time and manual effort.
Help me make natural black-background photographs with editable masks and optional shading. Preserve the actual photographed detail: legs, antennae, hairs, web strands, soft edges and transparent wings. No generated texture, invented anatomy or redraws. Keep original files untouched. Per-photo requests may change between iterations: keep a bee and flower, an insect plus a selected leaf portion or branch, a spider and web, or translucent dragonfly wings. I need to be able to review a result, give a specific correction, and repeat locally without starting over.

Propose an agent-assisted loop that translates my plain-language corrections into object selections and guide edits, handles model passes, QA and targeted reruns, and shows uncertainty. Ask me only about ambiguous artistic decisions; do not require me to trace every edge. This is a proposed capability, not something the current scripts already provide.

START WITH THE REFERENCES
Treat the supplied scripts as experimental references with hardcoded paths and coordinates, not a turnkey application. Inspect the final manifests and validation reports rather than assuming script defaults describe executed runs. Separate tested behavior from proposed improvements. Use the DOCX guide for context, the technical reference and model manifests for exact settings, and the examples for visual targets and failures. Do not copy environment snapshots into a supposed universal lockfile.

The ten-photo baseline used BiRefNet_dynamic-matting at 1184 × 1536 padded input, with 1157 × 1536 content for nine photos and 1156 × 1536 for the caterpillar, then resized alpha to native developed dimensions. It missed some fine anatomy and left some solid subject areas too transparent. Keep it as a benchmark or fallback, not the automatic best choice. The prototypes processed 8-bit RGB despite retaining 16-bit masters and masks; end-to-end high-precision foreground processing still needs implementation.

RECOMMENDED PIPELINE TO EVALUATE
1. Ingest, hash and validate the real file format, orientation, crop and color profile. Develop RAW at full resolution with a documented recipe and save a higher-precision aligned master. A mask is applied to this developed image, not written into the RAW. Do not infer sensor bit depth from a 16-bit output. Validate white balance and clipping before masking. The Pixel DNG tests had invalid decoder camera-WB coefficients despite AsShotWhiteXY metadata. The corrected ten-photo batch used explicit LibRaw daylight; the spider used a different approximate metadata-WB recipe. Preserve those distinctions.
2. Use guided SAM2 selection on an overview to express keep/remove groups. Let me amend points, boxes, selected objects and local regions. Build an editable three-zone trimap: confirmed background, uncertain coverage and genuinely opaque foreground. Leave hairs, uncertain edges, web and translucent wing areas appropriately uncertain; do not make an entire wing opaque.
3. Evaluate the tested SAM2.1 hiera-small plus ViTMatte-small-composition-1k approach. SAM overview was 1024 pixels; ViTMatte used native 1024-pixel tiles with 256 overlap, blended seams and locked known trimap regions. Plan coordinate alignment, boundary tiles, memory limits and seam checks. Validate CPU/GPU compatibility and output on my actual computer.
4. Build a review-and-repair loop. The guided tests used two full passes plus local corrections. The spider needed five confirmed background cores and a local matte to remove residue in leg gaps while protecting anatomy and the web outside the repair. Support scoped corrections, accepted-region locks, version history and same-crop comparisons. Flag ambiguity rather than silently discarding details.
5. Keep optional edge-color decontamination separate from alpha. Mask-only mode must preserve the developed RGB. The spider reference also includes a distinct approximate foreground-color correction in partial-coverage pixels. If proposed, save corrected RGB and its support separately, retain the untouched source and explain the limits. It is not recovery of missing detail.
6. Add optional, reversible inward edge shading after the mask is accepted. Preserve the base alpha. Use a separate black layer or effect with an editable shadow-weight mask. Let me change opacity, inward width, direction and protection per image, or disable it. The tested widths were 48 source pixels for the grasshopper and 88 for the dahlia at 3072 × 4080, with thin-feature protection. Tested maximum strengths were 12% and 24%; typical affected-edge opacity was nearer 3% and 6%. I may prefer the stronger version, but 24% is not an established global default. Protect antennae, hairs, web, true highlights and the central bee. Document encoded-sRGB versus linear-light behavior. Avoid double application of alpha or an already baked overlay opacity.
