## Risk and oracle design

The main consequences are silent pixel loss, copied anatomy at the border, accidental second alpha multiplication, wrong source/revision output, overwritten saved work, misleading acceptance labels, corrupted native authoring coordinates, uncontrolled image memory and unusable browser preview. Test real application paths with small synthetic fixtures and independent expected values; use spies only at expensive allocation/model or injected failure boundaries. Actual file round trips, HTTP, processes and browser behavior remain necessary.

Use uint16 values not divisible by 257 so 8-bit round trips cannot falsely pass. Include alpha 0, 1, 32768 and 65535, nonempty protected opaque and partial samples, nonzero shading and native subject pixels touching all edges. Compare input arrays/files before/after. Expected native composites come from the existing independently justified scalar formula and source contract; expected borders come from literal saved-backdrop values, never the framing helper under test.

A minimum literal oracle from P Task 1 uses a 2×1 native image, saved backdrop `[[11,12,13],[21,22,23]]`, margins left=1/right=2/top=1/bottom=0. The entire top output row must be `[[11,12,13],[11,12,13],[21,22,23],[21,22,23],[21,22,23]]`; native samples occupy exactly the two positions starting at `(1,1)`. A different non-black subject edge distinguishes backdrop extension from subject stretching.
