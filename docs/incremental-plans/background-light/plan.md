### Selected interfaces and contracts

The eight source-plan functions keep their names/signatures. `shape=(height,width)` is always native; `x/y` are equally shaped finite sample arrays and output is `(*x.shape,3)` uint16. Full generation calls the sampler in at most 64-row chunks. Sampling coordinates may lie outside native bounds for series extension; only stored centre/size controls are bounded. `enabled` never suppresses saved L16 generation.

```python
validate_background_light(settings: Any, width: int, height: int) -> None
normalized_background_light(settings: Any, width: int, height: int) -> dict[str, Any]
sample_background_light(shape: tuple[int, int], settings: dict[str, Any],
                        x: np.ndarray, y: np.ndarray) -> np.ndarray
make_background_light(shape: tuple[int, int], settings: dict[str, Any]) -> np.ndarray
combine_background_light(background16: np.ndarray, light16: np.ndarray,
                         *, enabled: bool) -> np.ndarray
validate_background_light_bindings(project: Path, directory: Path,
                                   manifest: dict[str, Any]) -> None
read_background_light(project: Path, directory: Path,
                      manifest: dict[str, Any]) -> np.ndarray | None
save_background_light(stage: Path, developed_id: str, shape: tuple[int, int],
                      settings: dict[str, Any]) -> dict[str, Any]
inherit_background_light(project: Path, parent: str | None, stage: Path,
                         developed_id: str, shape: tuple[int, int],
                         settings: dict[str, Any] | None,
                         *, assets: dict[str, Any]) -> dict[str, Any] | None
saved_backgrounds(project: Path, directory: Path, manifest: dict[str, Any],
                  *, light_off: bool = False
                  ) -> tuple[np.ndarray | None, np.ndarray | None]
```

`saved_backgrounds` returns `(base, displayed)` after validating both saved records. Missing B0 means zero only when combination/active fade requires an array; no-light legacy callers keep their existing `None`/black path. It does not decide foreground staleness: consumers retain their current BASE gates. It never mutates B0. Staging consumers use the same combiner with resolved stage operands, not a second formula. `inherit_background_light` must not create a record when parent lacks one; nonmatching root draft settings require explicit Apply. Enabled-only Apply inherits exact L16 and writes updated normalized settings/record; changed brightness/tint/geometry saves a fresh field even OFF.

Record exactly: schema1, `linear-srgb-background-light-v1`, developed_id, width, height, settings, light_sha256, settings_sha256. `background_light/light_rgb16.tif` is an asset; `background_light/settings.json` is a bound file equal to normalized recipe/record settings. Native editable names are `background_light_rgb16.tif`, `background_light_settings.json`. No other light inputs, native read regeneration, path-bearing settings or inferred source migration.

UI controls will use `backgroundLight...` IDs and domain functions such as `backgroundLightSettings`, `applyBackgroundLight`, `reloadBackgroundLight`, `renderBackgroundLightControls`; one independent record holds saved identity, draft version, dirty/stale state and submitted version. A separate per-shape map retains only session drafts. Reuse coordinate helpers/guarded actions; do not reuse a fade strength map or add a background-light preview backend. Existing saved image routes supply the comparison. Numeric fields use fractional input, strict blank/nonfinite checks and visible errors; the slider never rounds a saved numeric value. Turn OFF reads validated current saved settings rather than the form; no-record control is disabled and backend no-op/rejection cannot create a record.
