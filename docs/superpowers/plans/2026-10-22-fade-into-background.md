# Fade into background Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add one reversible Fade into background mode supporting oval-only, arcs-only and combined use, replacing inward shading when selected while retaining independent highlight protection and unchanged source, alpha, Shadow fade and framing controls.

**Architecture:** Reduce the enabled oval and independent one-sided curved arcs to one native-coordinate maximum-strength field, then apply shared protection/highlights and one canonical background blend. Retain existing alpha compositing and handle series framing against its output-coordinate background. Persist editable vectors alongside the combined W16 and extend current revision/preview/export contracts without per-arc RGB layers or a parallel processing pipeline.

**Tech Stack:** Existing Python 3.12, NumPy, Pillow, tifffile, SciPy, local HTTP viewer and vanilla JavaScript/Canvas; pytest and existing Node-based UI harness. No dependency, backend or model change.

**Spec:** [Agreed direction and detailed design](../specs/2026-10-22-fade-into-background-design.md). Read it before implementation; its numeric values and rendering contracts are normative for this plan.

## Global Constraints

- Planning only is authorized by the present request. Application implementation requires a subsequent execution instruction; no commits, pushes, PRs or private-source transmission are authorized.
- Add only **Fade into background**; retain inward shading as a mutually exclusive existing mode. Missing new fields retain legacy behavior.
- Rendered RGB can brighten or change colour. Preserve original captures, source/master assets, masks, alpha, locks, independently editable layers, background assets and framing geometry.
- Transparent exports keep faded RGB and unchanged alpha; deliver unfaded editable layers and effect operands. Framed exports of revisions with a spatial record retain compact files and also deliver a separate native editable companion, including when that record is disabled. Existing 8-bit transparent views remain honestly labelled.
- Preserve existing Shadow fade independently, including `amount=0.38` in the photographic case; do not reuse or reset its highlight setting.
- One independently enabled oval, an independently enabled group of up to 32 arcs with stable IDs and per-arc switches; use either or both without losing inactive settings.
- Native shape coordinates, fixed smoothstep, per-shape strength, strongest-wins overlap and one shared highlight-preservation setting; no automatic thin-detail or low-alpha attenuation.
- Per-shape directional monotonicity, not global monotonicity across arbitrary arcs. Arc end softness is lateral only; no trailing fade-out that brightens tips again.
- Preserve project locks, strict schemas, raw manifest identity, stale checks, atomic publication of each folder, local/offline operation and CSP. Paired exports are sequential with explicit partial/uncertain outcomes, not one atomic transaction. No new downloads or infrastructure.
- Use `rtk` commands; run focused tests during implementation and the full relevant suite once on the settled change. Never repeat successful tests without changed inputs or unresolved evidence.
- Preserve existing dirty work. Recheck branch/status before execution and Git operations; do not commit by implication from task checkboxes.
- Feature completion includes maintained user instructions, saved-file/export contracts, assisted-use guidance and an evidence/limitations record. Documentation is part of delivery, not a follow-up after completion.

## Review Focus

1. A coloured target and partial alpha must converge to the selected background without a dark rim or alpha change — Tasks 1, 3 and 4 tests.
2. Moving/removing/disabling arcs must clear their vacated field, old inward W must never remain underneath, and OFF must not revive it — Tasks 1/2/5.
3. Soft arc ends, opposing/crossing fields and oval/arc junctions must obey local guarantees without additive strength or a false global monotonicity claim — Task 1 math and Task 6 full photographic profiles.
4. Crops, rotation, shape IDs, delayed snapshots and series framing must not move shapes or use the wrong target/settings — Tasks 3–5.
5. Disabled/stale/tampered operands, accepted-base gates and interrupted publication must preserve usable revisions and independently editable settings — Tasks 2/3/5; actual browser and photographic evidence remains separate in Task 6.
